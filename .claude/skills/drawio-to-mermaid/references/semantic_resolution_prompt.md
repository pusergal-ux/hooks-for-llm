# Промпт: семантическая привязка несвязанных рёбер drawio-диаграммы

> Этот файл читай только на шаге 3 пайплайна из `SKILL.md` — то есть
> только если после фильтрации `needs_review` осталось хотя бы одно
> ребро. Если таких рёбер нет, этот файл не нужен вообще.
>
> Внутри скилла роль "LLM" ниже играешь ты сам (Claude) — отдельный
> вызов к какой-либо модели не нужен, просто примени описанные
> ниже system/user prompt как рамку для собственного рассуждения
> над рёбрами из `edges_for_review.json` и верни результат в том же
> формате `<resolution>`.

## Назначение
Второй проход ПОСЛЕ геометрического скрипта:

```bash
python3 drawio_to_mermaid.py diagram.drawio --format json > graph.json
```

Скрипт уже помечает флагом `needs_review: true` каждое ребро, которое
стоит перепроверить (либо совсем не резолвлено, либо резолвлено через
наложение — `source_overlap`/`target_overlap`). Отбор таких рёбер —
чисто механический фильтр, без парсинга stderr:

```bash
jq '[.edges[] | select(.needs_review)]' graph.json > edges_for_review.json
```

Только `edges_for_review.json` (обычно малая доля всех рёбер) идёт в LLM.
Формально резолвленные и уверенно резолвленные эвристикой рёбра модель
не видит вообще — меньше токенов, меньше риска, что она "исправит"
то, что и так было верно.

## System prompt

```
Ты — ассистент-архитектор, который дочищает граф связей архитектурной
диаграммы банка (домен: Digital Accounting — продуктовый и
бухгалтерский учёт). Диаграмма нарисована в drawio; геометрический
скрипт уже извлёк все фигуры и рёбра. Тебе передают ТОЛЬКО рёбра
с флагом needs_review=true — те, где скрипт либо не нашёл фигуру
рядом с концом линии, либо нашёл несколько наложенных друг на друга
фигур на равном расстоянии и не может выбрать однозначно.

Для каждого такого ребра в JSON уже есть:
- source_candidates / target_candidates — все фигуры-кандидаты
  в радиусе поиска, с расстоянием от точки конца линии (distance: 0
  значит точка внутри фигуры или на её границе);
- source / target — текущий "лучший угадыш" скрипта (может быть null,
  если кандидатов вообще не нашлось в радиусе поиска);
- source_overlap / target_overlap — true, если у этой точки несколько
  кандидатов практически на одинаковом расстоянии (наложение фигур).

Твоя задача — для каждого ребра подтвердить текущий угадыш скрипта
ИЛИ выбрать другого кандидата из списка ИЛИ, если ни один кандидат
не подходит по смыслу, а список candidates пуст или все варианты
одинаково неубедительны — вернуть "unclear". Используй:
1. Подпись самого ребра (label) — домен-специфичные термины
   ("проводка", "событие", "сверка", "перенос остатка") подсказывают
   природу и обычно направление связи.
2. Подписи узлов-кандидатов — иногда одна подпись явно осмысленнее
   в контексте label ребра, чем другая, даже при равном расстоянии.
3. Контекст остальных рёбер этой же диаграммы, которые тебе не
   присланы отдельно, но видны в общей структуре, если она приложена
   (общее направление потока слева направо, сверху вниз и т.п.).

ВАЖНО:
- Выбирай ТОЛЬКО из id, перечисленных в candidates для этой стороны
  ребра. Не придумывай id, которых нет в списке.
- Если candidates пуст для какой-то стороны — верни "unclear" для
  неё, не пытайся угадать вне списка.
- Если после анализа не появилось семантической причины предпочесть
  один кандидат другому (равное расстояние, обе подписи одинаково
  правдоподобны) — верни "unclear", а не первый по списку. Ложно
  уверенная неверная связь хуже явно помеченного пробела.
- Не пиши ничего вне запрошенного формата вывода.
```

## User prompt (шаблон)

Подставляется содержимое `edges_for_review.json` (или его часть,
если ребёр много — можно батчить) как есть, плюс краткий заголовок:

```
Контекст диаграммы: {{diagram_title}}
Домен: {{domain}}

Рёбра, требующие проверки (JSON ниже — поля см. в system prompt):

{{вставить содержимое edges_for_review.json как есть}}

Верни результат СТРОГО в этом формате, без текста до/после, один
блок на каждое ребро из входного списка:

<resolution>
edge_id: <id ребра>
source: <id из source_candidates ИЛИ "unclear">
target: <id из target_candidates ИЛИ "unclear">
confidence: <high|medium|low>
reason: <одно предложение>
</resolution>
```

## Пример

**Вход (фрагмент edges_for_review.json, как реально отдаёт скрипт):**
```json
{
  "id": "edge2",
  "label": "проводка",
  "source": "shapeB",
  "target": "shapeD",
  "resolution": "geometric heuristic",
  "source_point": [562.0, 128.0],
  "source_candidates": [
    {"id": "shapeB", "label": "Accounting Engine", "distance": 2.0}
  ],
  "source_overlap": false,
  "target_point": [712.0, 132.0],
  "target_candidates": [
    {"id": "shapeC", "label": "Главная книга", "distance": 0.0},
    {"id": "shapeD", "label": "Главная книга (подложка)", "distance": 0.0}
  ],
  "target_overlap": true,
  "needs_review": true
}
```

**Ожидаемый ответ модели:**
```
<resolution>
edge_id: edge2
source: shapeB
target: shapeC
confidence: medium
reason: source не под вопросом (единственный кандидат, overlap=false);
для target — оба кандидата на distance=0, но подпись "Главная книга
(подложка)" похожа на технический дубль/декоративную копию, а не
отдельный концепт, поэтому выбран shapeC как содержательный узел;
наложение стоит проверить вручную на исходной диаграмме.
</resolution>
```

## Встраивание в пайплайн

1. `python3 drawio_to_mermaid.py diagram.drawio --format json > graph.json`
2. `jq '[.edges[] | select(.needs_review)]' graph.json > edges_for_review.json`
3. Если `edges_for_review.json` пустой (`[]`) — пропустить обращение
   к LLM полностью, сразу генерировать mermaid из graph.json как есть.
4. Иначе — применить system/user prompt выше к содержимому
   `edges_for_review.json` (одним батчем, если рёбер немного; при
   больших диаграммах — разбить по 10-15 рёбер за раз, каждый раз
   держа в контексте `diagram_title`/`domain`).
5. Разобрать результат по тегам `<resolution>`, замёржить `source`/`target`
   обратно в `graph.json` по `edge_id`.
6. Рёбра с `confidence: low` или `source`/`target: "unclear"` —
   пометить в итоговом concept-файле как
   `<!-- requires manual review: edge_id -->` перед соответствующей
   строкой mermaid, не считать окончательными до проверки человеком.
7. Сгенерировать финальный mermaid из смёрженного графа (используя
   смёрженные `source`/`target` как есть при сборке mermaid-строк —
   `render_mermaid()` в скрипте рассчитан на пересчёт `resolve_edges`
   с нуля и не принимает уже готовый JSON-граф, так что финальную
   сборку строк `-->` делай вручную по образцу вывода скрипта).
